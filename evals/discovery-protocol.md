# Demand discovery evaluation protocol

Recorded 2026-10-16 before the resumed forward run produced its report. This is a
bounded engineering acceptance test, not a population-level accuracy benchmark.
The first live run and interrupted raw collection already existed; this is not a
preregistration made before all data collection.

## Task and material

Use the skill to discover solo-deliverable product opportunities in three real
task domains: multilingual video, freelancers, and small sellers. Start from
public posts and comments, preserve useful contrary cases, create a demand pool,
and produce a short decision report. The independent forward agent receives the
skill and raw source material, but not the baseline report or intended findings.
Supplement the original 13 Reddit posts / 65 comments with at least 12 new post
bodies and 70 individually retained, locatable comments. Parent-read X/LinkedIn
sources are explicitly attributed; they are not the forward agent's own browsing.

Freeze the first complete forward output before review. Subsequent corrections
must preserve that snapshot and disclose reviewer involvement. A count is an
inventory check, not a success criterion for research quality.

## Behavioral acceptance

| Check | Required observable behavior |
|---|---|
| Discovery without a predetermined product | A varied pool of concrete tasks across all three domains, including comment-derived tasks, before selecting opportunities |
| Context fidelity | Every selected task keeps actor, trigger, desired outcome, workaround and remaining friction aligned with its original context; uncertainty is explicit |
| Evidence fidelity | Exact excerpt references resolve; monetary/frequency claims retain their actual meaning; inferred fields do not masquerade as source statements |
| Counterevidence | Retain promotional, resolved and adjacent signals; a reply or accepted solution can narrow or reject an apparent opportunity |
| Corroboration | Group by discussion, deduplicate material, and seek an independent case for leading clusters; disclose singletons and convenience sampling |
| Commercial usefulness | Leading ideas specify a reachable buyer hypothesis, closest current alternative, narrow deliverable, agent/human boundary and an observable go/stop test |
| User control | Standalone discovery does not force personas or simulated interviews; saved research is resumable and report selections exclude unrelated history |
| Inspectable delivery | Export report plus separate linked need pool and evidence; replay from sanitized inputs without a model |

Review all shortlisted opportunities and all non-unknown payment/frequency fields.
Also review rejected cards and a sample of remaining fields, with the denominator
reported. A material unsupported claim that could change product selection blocks
acceptance until corrected and checked on a fresh request. Structural tests cannot
replace this review. Review selection is purposive, not random; report observed
errors rather than an accuracy percentage.

## Atypica comparison

Use its current public Scout/Product R&D documentation to define the shared core:
observe public discussion, synthesize user tasks, seek disconfirming context, group
opportunities and produce a decision artifact. Check our successful execution of
each operation against concrete saved artifacts. This can establish bounded
workflow coverage, not identical platform reach or overall superiority.

Historical actual Atypica scouting outputs can be checked against their originals
under the same context-fidelity criteria. Known errors are named regression cases,
not an independent paired accuracy benchmark. If a fresh Atypica run cannot execute,
record the actual cause; unavailable quota is never a quality win. Do not claim
better accuracy, complete product parity, real customer validation or a successful
head-to-head final-report comparison without those observations.

## Iteration and release

Record observed failures → narrow instruction/code changes → fresh behavioral
retest. Run appropriate CLI regressions and independent code review, validate the
skill, build a wheel, smoke-test both installation destinations and replay the
public example. Installation alone does not establish Claude model behavior.
Publish only sanitized sources, evaluation summaries and reproducible artifacts;
private API state, browser captures and credentials remain local.
